# 用 5.5 小时在 RTX 5090 上微调一个「会写证明」的数学小模型

> 记录一次完整的 QLoRA 微调实录：从 4 万条教材证明数据，到能写教材风格证明的 9B 模型。
> 含踩坑实录、前后对比，以及一个诚实的结论：风格会了，正确性还不会。

## 1. 背景：我想做什么

身边有位数学专业的朋友，在做一件很有野心的事：把 Springer 的 GTM 系列数学教材（500+ 本）自动化地转成 Lean 4 形式化代码，用编译器逐条验证。流水线已经跑通了 60+ 本，产出了一个庞大的数学知识库（27,000+ 概念、13,000+ 证明、6,500+ 习题）。

我作为一个计算机专业的人，看到这批数据的第一个念头是：**这能不能用来训练一个"解题机器"？**

于是有了这个实验：

- **模型**：Qwythos-9B（Qwen3.5 架构、94 亿参数、1M 上下文、Apache 2.0 开源）
- **数据**：从知识库里整理出的 40,443 条 SFT 样本（13,277 条"证明题" + 27,166 条"概念讲解"）
- **硬件**：AutoDL 租的 RTX 5090（32GB 显存），按量计费
- **方法**：QLoRA 4-bit 量化 + LoRA（r=16, alpha=32），单卡微调约 5.5 小时
- **结果**：模型学会了"教材证明的皮"，但正确性仍需验证闭环

## 2. 数据：从知识库到 SFT 样本

朋友的知识库（mathpkg 仓库）里，每个数学概念有 5 类文件：概念定义（YAML）、定理陈述（LaTeX）、英文讲解（Markdown）、证明、习题。

我做了一件简单但关键的事：**把它整理成两类标准 SFT 任务**，统一成 JSONL：

```json
{"task": "proof", "instruction": "请证明以下定理。", "input": "<定理陈述>", "output": "<完整证明>", "meta": {...}}
{"task": "explain", "instruction": "请详细讲解以下数学概念。", "input": "<概念信息>", "output": "<概念讲解>", "meta": {...}}
```

最终得到 40,443 条样本，覆盖代数、分析、拓扑、几何、数论、概率等 10 个数学领域。

## 3. 环境：RTX 5090 的踩坑实录

5090 是 Blackwell 架构（sm_120），这条路上的坑比想象的多，值得记录：

### 坑 1：torch 必须 cu128

Blackwell 显卡需要 CUDA 12.8 及以上，**PyTorch 2.7+ 且必须是 cu128 版本**。镜像自带的旧 torch 直接报 `no kernel image available`。正确姿势：

```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128
```

### 坑 2：torchaudio 版本不配套

环境里 torch 是 2.8+cu128，torchaudio 却是 CUDA 13 的版本，导入直接报 `libcudart.so.13 not found`。**必须版本完全对齐**：torch 2.8 ↔ torchaudio 2.8 ↔ torchvision 0.23。

### 坑 3：LLaMA-Factory 静默失败

训练框架选了 LLaMA-Factory，结果模型加载、数据 tokenize 全都正常，训练却**一步都不跑、以退出码 0 安静结束**——查了一天，怀疑是这个多模态模型（Qwen3.5 架构）和 sharegpt 数据管线的兼容性问题。最后绕开框架，直接用 TRL 手写训练脚本，一分钟跑通。

**教训：框架报错不可怕，可怕的是"不报错但也不干活"。**

### 坑 4：显存 OOM 的三连击

32GB 显存跑 9B 模型，第一版配置（batch 2 + 长度 2048）在第 50 步稳定 OOM——某条超长样本的 logits 计算需要额外 9GB。最后定为：**4-bit 量化 + batch 1 + 梯度累积 8 + 最大长度 1024**。样本平均才 945 token，1024 截断影响很小。

### 坑 5：慢速回退 vs 专用算子

Qwythos 用了混合注意力架构（Gated DeltaNet），不装专用算子会回退到"又慢又吃显存"的通用实现。装好 `causal-conv1d` + `flash-linear-attention` 后，GPU 从 37% 利用率冲到 100%，功耗拉满 526W/575W。

## 4. 训练配置与结果

最终训练配置：

| 参数 | 值 |
|---|---|
| 量化 | 4-bit QLoRA（bitsandbytes） |
| LoRA | r=16, alpha=32, dropout=0，全线性层 |
| 最大长度 | 1024 token |
| batch | 1 × 梯度累积 8（等效 8） |
| 学习率 | 2e-4，cosine，warmup 3% |
| 轮数 | 1 epoch（5,005 步） |
| 耗时 | 约 5.5 小时 |

结果：

- train_loss：**0.7176**（初始约 0.84）
- eval_loss：**0.6905**（400 条验证样本）
- eval 平均 token 准确率：**0.812**

loss 曲线在 TensorBoard 里一路下降，训练过程没崩——对第一次做微调的人来说，这已经是值得庆祝的里程碑。

## 5. 微调前后：风格变化有多大？

我拿同样的三道证明题分别问微调前/后的模型，差异非常直观：

**微调前（base）**——像是在"讲怎么证明"：

> 1. **Identify the theorem**... 2. **Determine the appropriate proof strategy**... 3. **Structure the proof**...

**微调后**——直接开证：

> The theorem is the Cauchy theorem... **Proof.** Proceed by induction on $|G|$...

用文本统计量化一下：

| 指标 | 微调前 | 微调后 |
|---|---|---|
| 元讨论词（Identify/Strategy/Plan） | 3 次 | 0 次 |
| "第几步"式规划列表 | 4 处 | 0 处 |

模型甚至学会了语料里的口癖——有一道题的回答里出现了"the proof section is truncated, I will reconstruct..."，这正是教材抽取流水线的常见措辞。**风格迁移是肉眼可见的，且可归因到训练语料。**

## 6. 诚实时刻：风格会了，正确性还不会

但别高兴太早。拿柯西定理那道题细看，微调后的证明在**类方程**一步声称"每个非中心共轭类的大小都被 p 整除"——**这是错的**（反例：S₃ 中 p=2 时，对换的共轭类大小是 3）。

正确证法的方向恰好相反：要找**一个不被 p 整除**的类大小，从而得到阶含 p 因子的真子群，再归纳。

这说明什么？**SFT 只教会了模型"写证明的样子"，没教会它"每一步都经得起推敲"。** 没有验证闭环，它会把错误步骤写得信心满满——这是所有 LLM 数学证明的通病，也是下一步要啃的硬骨头：

1. 让数学专业的人抽检 20–50 道题，统计真实正确率；
2. 接上 Lean 编译器验证闭环（朋友的流水线现成的）；
3. 用更强的模型当裁判（LLM-as-judge）先筛一遍错题。

## 7. 总结

这一版实验的收获：

- ✅ 完整跑通"教材知识库 → SFT 数据 → QLoRA 微调 → 合并 → 部署"全链路；
- ✅ 微调后模型风格上"会写证明"了，风格迁移可量化；
- ✅ 一整套可复现的脚本和环境配置；
- ❌ 证明正确性没有解决——这是所有 LLM 数学模型的共同关卡。

5.5 小时、40,443 条数据，换来一个"会写教材风格证明草稿"的模型。接下来，验证闭环才是从"看起来对"到"真的对"的那座桥。
